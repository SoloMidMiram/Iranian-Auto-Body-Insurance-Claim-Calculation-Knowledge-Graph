GitHub exposed two unresolved Codex review threads.

1. Apply the authorized review's evidence-confidence cap
   Status: FIXED AND RESOLVED

   The finding was valid at 938e4f6. A review authorization recorded an
   evidence_confidence_cap of 0.8, but direct compute() returned 0.95 while
   Review.calculate() returned 0.8. Because calc and json use authorize() followed
   by compute(), both CLI paths bypassed the cap.

   The fix applies the immutable review-issued cap inside compute() after formula
   confidence finalization. Review.calculate() now delegates to the same path.
   Direct compute, Review.calculate, calc, and json all return 0.8 and add
   EVIDENCE_CONFIDENCE_REDUCED for the missing-EVT_PHOTOS reproduction.

   Added direct authorization and CLI regressions. Updated README confidence
   documentation and repository test counts.

2. Prevent provenance from overriding sealed authorization fields
   Status: ALREADY FIXED; THREAD DOCUMENTED AND RESOLVED

   Commit 938e4f6 stores provenance as immutable canonical JSON and returns only
   detached decoded copies. provenance_record() overlays sealed issuer, decision,
   claim_hash, and issued_at after custom provenance.

   The regression now explicitly mutates those reserved fields as well as reviewer,
   approved_overrides, classification, and policy snapshot values. Later emitted
   provenance remains unchanged.
